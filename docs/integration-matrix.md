## Исправления исходного backend при интеграции

- Возвращены persistence и return из apply_action; устранён HTTP 500.
- Собранная дебиторка увеличивает ликвидность и уменьшает доступный долг контрагентов. Есть единый журнал успешного исполнения, видимый портфелю, и защита повтора.
- Автопилот не исполняет платные/непредодобренные действия вне согласованных границ; результат отказа не теряется.
- Стресс — отдельный просмотр, кнопки исполнения отключены до сброса. Мост учитывает новый платёж и амортизированную стоимость.
- Ручное одобрение создаёт новое Decision и Offer. Банковский transition не принимает клиентское согласие и не выдаёт кредит в обход /accept.
- Проверены диапазоны чисел и структура YAML, повторная валидация при активации, индикатор «вероятности» не выдаётся за ML.
- Добавлены имена и ИНН в ответы заявок, сохранение конструктора, совместное согласование и настоящее локальное файловое хранилище.

## Честные границы прототипа

БКИ/ЕГРЮЛ/ФНС/ОФД/дебиторка — локальные моки. Источники не обновляются непрерывно внешними банковскими системами. 1С/Ozon/WB не подключены. Документы из seed имеют только метаданные; новые загруженные файлы хранятся полностью. ПЭП, отправка приглашений/напоминаний, реальные платежи и договоры не выполняются. По умолчанию копилот шаблонный. Метрики 30+ и дохода модельные. Исторические артефакты аудита во вложенной папке описывают версию до интеграции; актуальная проверка — `integration-verification.md`.
