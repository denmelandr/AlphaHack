# Submission checklist — слайд 7 кейса

Этот файл — контрольный список материалов, которые должны быть доступны жюри в GitHub-репозитории.
Он составлен по разделу «Технические требования к решению и формат сдачи» презентации кейса.

## 2. Release checklist

Выполнить на финальной версии, которая будет отправлена жюри:

```bash
# 1. Проверить чистую конфигурацию и сборку
docker compose config --quiet
docker compose build

# 2. Поднять систему
docker compose up -d

# 3. Проверить health и тесты
curl -fsS http://localhost:8080/health
docker compose exec -T backend python -m pytest -q
bash scripts/verify_submission.sh

# 4. Проверить UI вручную по docs/DEMO_RUNBOOK.md

# 5. Зафиксировать версию
cat VERSION
git status --short
git rev-parse HEAD

# 6. Создать неизменяемую метку именно после финальных изменений
git tag -a submission-v0.1.0 -m "Submission release v0.1.0"
git rev-parse submission-v0.1.0
```

Последние две команды должны выполняться только после того, как все файлы проверены.
В форму сдачи передать URL репозитория, tag `submission-v0.1.0` и hash коммита, на который
указывает tag. Если репозиторий приватный, предоставить доступ аккаунту жюри `alfa-hack-2026`.

## 3. Что не требуется для проверки

- реальные банковские API;
- реальные персональные данные;
- платные API или внешние подписки;
- GPU и обязательный запуск LLM;
- email, SMS, мессенджеры и телефонные звонки;
- реальное подписание или перечисление денежных средств.

Все перечисленные ограничения выполнены явно: интеграции локальные и синтетические,
подписание и выдача моделируются, а основной сценарий проходит внутри веб-продукта.

## 4. Быстрый smoke-check для эксперта

```text
1. docker compose up --build
2. открыть http://localhost:5173
3. войти demo@alfa.ru / demo123
4. открыть «Ромашку» → показать решение и путь к одобрению
5. открыть «Весну» → показать радар ликвидности и дебиторку
6. включить автопилот → «Прогнать сейчас» → показать журнал
7. открыть «Портфель» → показать ранние предупреждения и метрики
8. открыть «Консоль политики» → изменить YAML → симулировать
```

## 5. Текущее ограничение демо

Автоматический seed выполняется при старте backend и является идемпотентным. Если эксперт
хочет пройти чистый пользовательский путь с нуля, необходимо удалить volume PostgreSQL
командой `docker compose down -v`, затем повторить запуск. Это влияет только на
предзаполненные данные, а не на исходный код.
