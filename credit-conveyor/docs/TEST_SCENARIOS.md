# Тестовые сценарии

## Автоматические тесты

Юнит-тесты движков (скоринг, политика, финансовые расчёты):

```bash
docker compose exec backend python -m pytest -q
```

Покрывают: границы балла, сравнение хороших и плохих профилей, влияние залога и
поручителя, жёсткие стоп-факторы, пороги одобрения/контрпредложения/отказа,
запрос данных при недоступном источнике, аннуитет и амортизацию графика.

## Ручной сквозной сценарий (end-to-end)

Демо-доступы и ожидаемые исходы — в корневом `README.md`.

### Клиент: от потребности до результата
1. Войти как `client@demo.ru` / `client123`.
2. «Новая заявка» → подбор продукта по опросу → калькулятор (видна переплата и
   сравнение с ожидаемой прибылью) → документы (загрузить все) → отправка.
3. Заявка автоматически проходит валидацию, обогащение, скоринг и решение.
4. Для контрпредложения открыть «Путь к одобрению»: двигать ползунки и включать
   залог/поручителя — вероятность одобрения и ставка пересчитываются в реальном
   времени. Нажать «Запросить пересмотр человеком».

### Разные исходы решения
- `client@demo.ru` (Ромашка) — контрпредложение.
- `client2@demo.ru` (Берёзка) — одобрение.
- `client3@demo.ru` (Осина) — отказ, заблокирован счёт (жёсткий стоп-фактор).
- `client4@demo.ru` (Клён) — отказ по баллу.

### Банк: управление процессом
1. Войти как `underwriter@bank.ru` / `bank123`.
2. Открыть заявку в очереди → профиль, разбор балла, решение, трасса.
3. «Копилот андеррайтера» → саммари, аномалии, черновик обоснования.
4. По заявке в ручном разборе — одобрить / отказать / запросить данные.

### Консоль политики (риск-менеджер)
1. Войти как `risk@bank.ru` / `risk123` → «Консоль политики».
2. Изменить в YAML `approve_min`/`counter_min` → «Симулировать на последних N».
3. Сравнить долю одобрений активной и кандидатной политики, увидеть изменившиеся
   решения. «Сохранить как версию» → «Активировать» (champion/challenger).

### Сопровождение после выдачи
1. По одобренной заявке клиент принимает оффер.
2. Банк проводит подписание и выдачу → открывается кредитный счёт.
3. Карточка сопровождения: сигналы по денежному потоку и меню превентивных
   действий (реструктуризация, перенос даты, revenue-based, умный остаток,
   рефинансирование) с расчётом последствий и применением в один клик.
4. Открыть заявку «Весны» и проверить 60-дневный прогноз, дату разрыва, цену
   бездействия и сравнение стоимости вариантов.
5. Проверить радар контрагентов: рискованный должник не входит в собираемую
   дебиторку, а надёжная часть используется оптимизатором первой.
6. Включить автопилот с `max_bridge=100000`, запустить его и убедиться, что
   действие записано в журнал, а превышающий лимит мост не применяется.
7. Открыть банковский портфель и проверить, что Весна попала в early-warning,
   а метрики показывают превентивное действие.

### Персональные предложения
1. Открыть карточку здорового клиента.
2. Проверить, что предложения подобраны по ОКВЭД, выручке и типу продукта.
3. Убедиться, что скидка относится к дополнительным банковским продуктам и не
   уменьшает ставку по действующему кредиту.

### Надёжность и ограничения
- `GET /health` возвращает `{"status":"ok"}`.
- `docker compose config --quiet` завершается успешно.
- При выключенном LLM основной сценарий и копилот в шаблонном режиме продолжают работать.
- При чистом запуске seed создаёт одинаковый синтетический набор и не дублирует его
  при повторном старте.
