# Demo runbook для жюри

Цель показа — за 7–10 минут продемонстрировать не набор экранов, а связанный процесс:
клиент → конвейер → банк → выдача → сопровождение → портфель.

## 0. Подготовка

```bash
docker compose up --build
```

Открыть http://localhost:5173 и войти через `demo@alfa.ru` / `demo123`.

Если нужен полностью чистый seed:

```bash
docker compose down -v
docker compose up --build
```

## 1. Клиентская заявка и объяснимость — 2 минуты

1. Открыть заявку «Ромашки».
2. Показать:
   - статус и трекер заявки;
   - обогащение из БКИ/ЕГРЮЛ/ФНС/ОФД;
   - scorecard с факторами и вкладом в балл;
   - решение «контрпредложение».
3. Открыть «Путь к одобрению».
4. Изменить сумму или срок, добавить залог/поручителя.
5. Показать, что условия пересчитываются через тот же scoring + policy engine.
6. При необходимости нажать «Запросить пересмотр человеком».

Фраза для объяснения: клиент видит не только ответ банка, но и управляемый путь к
приемлемым условиям.

## 2. Сопровождение Весны — 3 минуты

1. Открыть заявку «Весны» в статусе `SERVICING`.
2. Показать кредитный счёт и прогноз ликвидности.
3. Обратить внимание на:
   - дату и размер кассового разрыва;
   - цену бездействия;
   - общую дебиторку;
   - сумму от рискованного должника;
   - реально собираемую часть.
4. Передвинуть ползунок падения выручки на 45%.
5. Показать таблицу вариантов и их стоимость.
6. Объяснить продуктовую логику: сначала вернуть собственные деньги бизнеса, а не
   автоматически выдавать новый долг.

## 3. Автопилот — 1 минута

1. В блоке «Автопилот» включить режим.
2. Установить лимит моста, например 100 000 ₽.
3. Нажать «Сохранить правила».
4. Нажать «Прогнать сейчас».
5. Показать журнал применённого действия.

Важно подчеркнуть: бесплатное/разрешённое действие может выполняться автоматически,
но новый долг выше лимита не создаётся без решения человека.

## 4. Банковская консоль — 2 минуты

1. Открыть «Портфель».
2. Показать:
   - Весну в очереди раннего предупреждения;
   - запас прочности;
   - сумму под риском;
   - применённое превентивное действие;
   - модельный эффект по портфелю.
3. Открыть «Консоль политики».
4. Изменить `approve_min` или `counter_min` в YAML.
5. Нажать «Симулировать на последних N».
6. Показать сравнение active/challenger и аудит изменений.

## 5. Завершение

Закончить связкой:

> Мы не ждём просрочки. Система заранее находит дату и причину разрыва, проверяет,
> можно ли вернуть деньги клиента через дебиторку, сравнивает стоимость решений,
> автоматизирует безопасные действия и поднимает риск на портфельный уровень банка.

## Ожидаемые результаты

- «Берёзка» — стабильный кредит без раннего предупреждения;
- «Весна» — раннее предупреждение и радар контрагентов;
- «Ромашка» — объяснимое контрпредложение;
- «Клён» — отказ по баллу;
- «Осина» — отказ по стоп-фактору блокировки счёта.
