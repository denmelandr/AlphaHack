# Умный кредитный кабинет

Единое приложение: наш адаптивный интерфейс Альфа-Бизнеса (React 19 + TypeScript + Vite + Alfa Core DS) и FastAPI из `credit-conveyor/backend`. PostgreSQL, миграции Alembic, Redis и локальные моки сохранены.

## Требования к окружению

- Docker Engine / Docker Desktop с Linux-контейнерами и Docker Compose **2.20+** (вложенный Compose использует `include`).
- Linux, macOS или Windows с WSL2. Рекомендуемый бюджет для демо: 4 CPU, 8 ГБ RAM и 5 ГБ свободного диска; это рекомендация, минимальная конфигурация отдельно не измерялась.
- Свободные порты: 5173, 8080, 8001, 5432, 6379. Интернет нужен для первой загрузки образов и зависимостей. Swagger по умолчанию загружает UI-ресурсы с CDN.
- Для разработки вне Docker: Node.js 22.6+ с поддержкой `--experimental-strip-types`, pnpm 10.11.0; Python 3.12 для backend. GPU для стандартного демо не нужен.

## Запуск одной командой

Получить проект и перейти в корень:

```sh
git clone https://github.com/denmelandr/AlphaHack.git
cd AlphaHack
```

Из этой папки:

```sh
docker compose up --build -d
```

- Сайт: http://localhost:5173
- Swagger: http://localhost:8080/docs
- API через фронтенд: http://localhost:5173/api/health
- Моки источников: http://localhost:8001/docs

Сервисы публикуются только на localhost. Именованные тома `pgdata` и `uploads` сохраняют БД и файлы после перезапуска. Миграции и идемпотентный seed выполняются при запуске backend. Подписание, выдача, автопилот и все финансовые операции — синтетическая модель. Реальные деньги и сообщения не отправляются.

## Конфигурация

Для стандартного синтетического демо `.env` не обязателен. Для настройки скопируйте `.env.example` в `.env` **в корне проекта**. После изменений пересоздайте контейнеры командой запуска.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `POSTGRES_USER` | `conveyor` | Пользователь БД |
| `POSTGRES_PASSWORD` | `conveyor` | Пароль локальной демо-БД |
| `POSTGRES_DB` | `conveyor` | Имя БД |
| `JWT_SECRET` | `dev-secret-change-me` | Ключ подписи JWT; заменить при публикации |
| `BANK_INVITATION_CODE` | пусто | Регистрация банковских сотрудников закрыта, пока код не задан |
| `LLM_ENABLED` | `false` | Использовать Ollama для текстов копилота |
| `LLM_MODEL` | `qwen2.5:7b-instruct` | Модель Ollama при включённом LLM |

`DATABASE_URL`, `REDIS_URL`, `INTEGRATIONS_URL`, `CORS_ORIGINS` и `OLLAMA_URL` задаются внутри `compose.yaml`; простое добавление их в корневой `.env` не переопределяет эти строки. `VITE_API_URL` используется только при сборке/разработке frontend; стандартный путь — `/api` через nginx.

### Опциональная LLM

В `compose.yaml` есть закомментированный пример сервиса Ollama. Чтобы включить его, раскомментируйте сервис и добавьте объявление `ollamadata:` в раздел `volumes`, запустите Ollama и загрузите модель: `docker compose exec ollama ollama pull qwen2.5:7b-instruct`. Затем задайте `LLM_ENABLED=true` в корневом `.env` и пересоздайте backend. Память и скорость зависят от модели и оборудования; этот режим не входит в обязательный запуск демо. При недоступности модели копилот возвращается к шаблонам.

## Демо-доступ

| Логин | Пароль | Возможности |
|---|---|---|
| demo@alfa.ru | demo123 | Клиент и банк; все синтетические компании |
| client@demo.ru | client123 | Ромашка: контрпредложение |
| client2@demo.ru | client123 | Берёзка: здоровый выданный кредит |
| client3@demo.ru | client123 | Осина: отказ, заблокирован счёт |
| client4@demo.ru | client123 | Клён: отказ по баллу |
| client5@demo.ru | client123 | Весна: радар и сопровождение |
| underwriter@bank.ru | bank123 | Очередь, разбор, пересмотр, копилот |
| risk@bank.ru | risk123 | Политика и активация версий, портфель |

У обычных пользователей роль подтверждает `/auth/me`, клиент видит только свою компанию. Только специальный серверный `demo` открывает оба набора инструментов. Переключателя ролей нет. Для регистрации предпринимателя нужны бизнес и ИНН; вход существующих компаний выдаётся администратором. Регистрация банковского сотрудника по умолчанию закрыта: `BANK_INVITATION_CODE` должен быть задан на сервере. Пароли не хранятся в браузере; JWT находится в sessionStorage. Для production нужны SSO/MFA, HttpOnly cookie, отзыв сессий и дополнительные меры из документа по безопасности.

## Что работает

- Опрос и каталог из API; калькулятор с графиком, тремя сценариями, задержкой прибыли и проверкой денежного потока. Сервер `/calc` подтверждает платёж и переплату, локальная формула даёт мгновенный предварительный отклик.
- Серверные черновики, четыре шага, сохранение шага, readiness, редактирование NEEDS_INFO. При переносе расчёта обновляются параметры и продукт черновика.
- PDF/JPG/PNG до 5 МБ: настоящая загрузка, скачивание и удаление. Файлы — локальный том, доступ проверяет API. Старые seed-документы имеют только метаданные, скачать несуществующий файл нельзя.
- Автоматическая проверка → БКИ/ЕГРЮЛ/ФНС/ОФД/дебиторка (моки) → scorecard → policy → approve/counter/need_info/decline.
- «Путь к одобрению»: сумма, срок, залог, поручитель; серверный пересчёт, факторы и причины; выбранные условия можно сохранить. Показатель approval_probability — учебный индикатор между порогами, не калиброванная вероятность ML.
- Пересмотр человеком: комментарии и новые решения записываются в БД, ручное одобрение формирует новый оффер. Клиентское принятие условий нельзя обойти банковским transition.
- Трекер по серверным событиям; при открытом экране обновление каждые 10 секунд. Реального ETA нет, фиктивный срок не отображается.
- 60-дневный радар, стресс выручки и расходов, дебиторка, рискованные должники, сбор своих денег, оптимизатор с ценой в рублях, цена бездействия.
- Перенос даты, продление, процент выручки, умный остаток, рефинансирование, факторинг и мост. Исполненные действия отражаются в условиях, остатке, журнале и портфеле. Повтор того же действия блокируется.
- Автопилот: бесплатные закрывающие действия или предодобренный мост в лимите; отказ/результат виден в журнале. Исполнение стресс-прогноза отключено: это what-if, а не базовый сценарий кредита.
- Награды и отраслевые кросс-предложения без изменения ставки кредита; портфель ковенант, ранних предупреждений и модельного эффекта.
- YAML-политика, проверка структуры, shadow на фактической истории (до 500), версии, аудит; сохранение и активация доступны risk_admin и demo.
- Копилот из backend: сводка, аномалии, редактируемый черновик и TXT. По умолчанию шаблон; Ollama подключается настройками backend.
- Совместная заявка: задачи бухгалтера, сотрудника, директора, серверная проверка ролей, история и внутренняя демо-подпись. Юридическая ПЭП и приглашения участников пока не реализованы.

История данных из прежнего локального прототипа не удаляется из браузера, но не смешивается с серверными пользователями и заявками. Все рабочие решения и действия теперь используют FastAPI, прежний локальный scorecard не подключён к рабочим экранам.

## Разработка и проверки

```sh
# backend + зависимости, без nginx
docker compose up -d --build backend
# зависимости фронтенда
pnpm install --frozen-lockfile
# Vite на 5173; /api направляется на FastAPI 8080
bash start.sh
# проверки
pnpm build
pnpm test
docker compose exec -T backend python -m pytest -q
```

Перед запуском Vite остановите контейнер frontend, если он занимает 5173: `docker compose stop frontend`. Обратное переключение: остановите Vite и выполните `docker compose up -d frontend`.

## Состав

- `src/connected/` — наш дизайн, подключённый к реальному API, общая выбранная заявка и серверное состояние.
- `src/api/client.ts`, `src/auth/` — транспорт, серверные вход/регистрация/права.
- `src/components/ui/`, `src/style.css`, `src/lab/lab.css`, `src/mobile.css` — компоненты и адаптивный стиль.
- `credit-conveyor/backend/` — домен, миграции, тесты; `integrations-mock/` — синтетические источники.
- `docs/integration-matrix.md` — сверка функций и ограничения.
- `credit-conveyor/docs/` — исходные архитектура, сценарии, Postman и спецификация. `docs/openapi.json` — актуальный контракт интегрированной сборки.

1С / Эльба и Ozon / WB не являются подключёнными источниками этого backend. Их отсутствие явно отмечено в профиле. Метрики просрочки/дохода — модельные оценки, а не измеренная статистика реального банка. Для реальных документов потребуются антивирус, объектное хранилище и политика доступа/хранения.

## Остановка и сохранность данных

`docker compose down` останавливает приложение и сохраняет тома. Для полного сброса **с удалением всех демо-заявок и загруженных файлов**: `docker compose down -v`, затем повторный запуск. Идемпотентный seed при обычном рестарте не сбрасывает пользовательские действия.
